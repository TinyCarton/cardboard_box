# cardboard_box

A Minecraft **1.20.1** mod that lets you pick up **any block** with a cardboard box and put it back
later with its block state and block entity data intact.

## Features

| Action | Result |
| --- | --- |
| **Right-click** a block with an empty box | The block becomes a box; its state (and block-entity NBT, if any) is stored, consuming one box |
| **Right-click** a placed box | Only the box is taken: the stored block is restored in place and you receive an empty box |
| **Empty box right-clicked** | The empty box itself is picked up |
| **Sneak + right-click** a placed box | Picks up the box together with the stored block (content travels in NBT) |
| **Left-click** a placed box | Restores the stored block and returns an empty box |
| Tooltip | Shows which block is stored inside |

Behaviour notes:

- **Any block can be stored.** Blocks without a block entity keep only their block state;
  blocks with one (chests, furnaces, machines) also keep their full NBT.
- **The original state is preferred on restore.** Facing, connections and waterlogged survive;
  if that state cannot survive at the target position (for example a torch in mid-air) the
  placement context is used to recompute it.
- **Neighbour updates are triggered.** Picking up uses `Block.UPDATE_ALL` (neighbours + clients)
  and placing calls `updateNeighborsAt`, so redstone, fences and support checks react immediately.
- A placed box has four horizontal facings only (`facing=north/east/south/west`) and faces the
  player when it is created.

## Whitelist and blacklist

| Mechanism | Default | Source |
| --- | --- | --- |
| Whitelist | **enabled** | `config/cardboardbox_whitelist.json` |
| Blacklist | **disabled** | built-in list (`VanillaHandler`) + `tile_ban_list` in the common config |

- Both can be enabled at the same time; **the blacklist takes priority**.
- The whitelist is not hardcoded. On first launch the file is generated by scanning the registry
  for every block that has a block entity:

```json
{
  "blocks": [
    "minecraft:chest",
    "minecraft:furnace",
    "minecraft:barrel"
  ]
}
```

- Toggles: `WhitelistSettings.EnableWhitelist` and `BlacklistSettings.EnableBlacklist`
  (Forge / NeoForge) or `whitelistEnabled` / `blacklistEnabled` (Fabric).
- A block rejected by the whitelist shows `block.cardboardbox.cardboard_box.notWhitelisted`.

## Building

Requires **JDK 17**.

```bat
set JAVA_HOME=C:\Program Files\Java\jdk-17
gradlew.bat build
```

Output: `build/libs/cardboardbox-1.20.1-1.0.0.jar` — ForgeGradle reobfuscates it automatically, so the jar can be dropped into `mods/` as is.

| Toolchain | Version |
| --- | --- |
| Minecraft | 1.20.1 |
| Forge | 47.4.29 |
| ForgeGradle | 6.x (Gradle 8.6) |
| Mappings | Mojang official |
| Java | 17 |

Other tasks: `gradlew.bat runClient`, `gradlew.bat runServer`.

> `Unsupported class file major version` means Gradle was started with a newer JDK.
> Either set `JAVA_HOME` as above or uncomment `org.gradle.java.home` in `gradle.properties`.

## Extending

Adapting blocks from another mod (soft dependency; only runs when that mod is loaded):

```java
public class CreateHandler extends ModHandler {
    private ForgeConfigSpec.BooleanValue allowShafts;

    @Override
    public void build(ForgeConfigSpec.Builder b) {
        allowShafts = b.define("Create.allowShafts", true);
    }

    @Override
    public void load(ForgeConfigSpec config) {
        if (!allowShafts.get()) {
            HandlerManager.INSTANCE.banBlockEntity(BlockEntityType.SHAFT);
        }
        HandlerManager.INSTANCE.registerHandler(SomeModBlocks.MACHINE.get(), new Handler() {
            @Override
            public void postPlaceBlock(Player player, Level level, BlockPos pos, InteractionHand hand,
                                       Direction dir, float hx, float hy, float hz, BlockState state, CompoundTag data) {
                // rebind multiblocks, restore the owner, refresh capabilities, ...
            }
        });
    }
}
```

Register it in the `CardboardBox` constructor:

```java
ModHandler.modSupportHandlerMap.put("create", CreateHandler.class);
```

The common config lists every registered block entity type (including other mods);
`BlackListSettings.BlackListMobSpawners` controls spawners. Block-level bans live in
`VanillaHandler`.

## Porting to another version / loader

The core logic only depends on the `Block` / `BlockEntity` / `BlockItem` lifecycle; what changes is
the registration, event and config layer:

- **Registration**: `DeferredRegister` → the target loader's registry API; `@Mod` /
  `FMLCommonSetupEvent` → the matching entry point.
- **Config**: `ForgeConfigSpec` → the target loader's config system (`ModHandler` /
  `VanillaHandler` are the only coupling points).
- **Keep the NBT keys** for save compatibility: item `storedItem` / `tileData`,
  block `storedTile` / `tileData`.
- **The box block must be registered as a valid block of its `BlockEntityType`**, otherwise the
  chunk reload check drops the block entity and the stored content is lost.
- Block states are stored as `Block.getId` / `Block.stateById` integers, which depend on registry
  order. If the target environment cannot guarantee that order, switch to
  `NbtUtils.writeBlockState` (storing `Name` + `Properties`).
- Double blocks (beds, doors, tall flowers) currently move only the clicked half; the other half
  drops or disappears according to vanilla rules.
